## 2026-08-12: プラクティスを作り直し（横から潜る・手組みのコース）

初版への指摘を受けての改定。

### やったこと

- **輪にくぐる向きを持たせた**。その向きに輪の面を横切ったときだけ通過。
  上から乗っても逆向きに抜けても通らない。
  判定は「前のフレームと今のフレームを結んだ線分が面を越えたか」で見る ――
  位置だけで見ると輪の中に入り込んだ時点で通ってしまい、横から潜る意味がなくなる
- 見た目を**くぐる向きに潰した楕円**にした（潰し 0.30）。潰れている方向が入る向きを表す。
  矢印も添えて、形と矢印のどちらでも読めるようにした
- **配置と順番を全ステージ手で組んだ**。上昇と下降 → 折り返し → 宙返り → スプリットS →
  インメルマンターン → 八の字 → ひと回り → 連続旋回 → 総仕上げ、と必要な機動が増える。
  ステージ名を画面に出すので、何の練習かが分かる

### つまずいた点

**手で置いた輪が、機体の旋回半径に合っていないと辿れない。** 最初に組んだ
ステージ 8〜10 は自動操縦がどうしても回れなかった。原因は3つとも配置側だった。

1. 縦に抜ける輪の手前が地面の下になる置き方をしていた
2. 一周コースの角で、次の輪が「進行方向と逆側」にあった
3. 折り返しの輪を地面すれすれに置き、上にも下にも回れない場所を作っていた

宙返りが 206×321px であることを基準に、折り返しの上下差を 320px 前後、
横幅を 200px 前後に揃えたら通るようになった。

もう1つ、**同じ場所に輪を2つ置くと番号が重なって読めない**。
総仕上げは同じ周回を2度使う形にしていたが、重ならない配置に組み直した。

  （毎秒6往復、濃さ 0.75 ⇄ 0.28）。見ただけで「今は当たらない」と分かるように

## 2026-08-12: コンピュータ操縦（1人プレイ / デモ）

### やったこと

「デモプレイできるように 2P をコンピュータ操縦で1人プレイできないか」という要望への対応。

- `src/ai/Pilot.ts` を追加。**AI は人と同じものしか出さない** ―― 機首の引き具合・
  ロール・スロットル・7.7mm・20mm の5つだけ。機体の中身を直接いじる近道は作っていないので、
  人に出せない動きにはならず、失速も墜落も同じように起きる
- 考え方は「機首をどこへ向けたいか」を毎フレーム1つの角度に決めるだけ。
  優先順位は **地面が近い → 失速している → 狙う相手の未来位置**。
  最初の2つを最優先にしないと、AI は戦う前に墜ちる
- **ロールを実機と同じ理由で使う**。機首を回すのに「押す」より「引く」ほうが素直なので、
  押し続けることになる場面では背面に返して引きに変える。
  ただし地面や失速から逃げている最中は回っている余裕がないので我慢する
- 腕前は3段階（弱・普通・強）。狙いの許容範囲・迷ってから動くまでの間・
  未来位置の読み・狙いの揺らぎ・撃ちはじめる距離・20mm を使うかが変わる
- 切り替えはキー1つで巡回（切 → 弱 → 普通 → 強 → 切）。**1P = V、2P = C**。
  2P を任せれば1人で遊べ、両方に任せればデモとして眺められる
- 誰が操縦しているかは計器の下に出しておく。切り替えた瞬間は画面中央にも出て、消える

### 実測して直した3点

最初の実装は、CPU 同士が 15秒で 11対1 になり、地面にもよく墜ちていた。
ゲーム画面の中で更新だけを高速に回す計測を書いて、原因を1つずつ潰した。

1. **引き起こしを「1.1秒先の高さ」で判断する**。今の高さだけで見ると、
   突っ込んでいる最中は手遅れになる。宙返りの半径が 135px あるうえ、
   迷ってから動くまでの間もあるため
2. **狙う高さに底を設ける**（地面から 150px）。地面すれすれの相手を追って
   一緒に突っ込まないようにする。撃つのを諦める代わりに墜ちない
3. **失速させないために迎え角そのものを見る**。失速角の 0.8 倍を超えたら舵を緩める。
   速度で加減する案を先に試したが効かなかった ―― 失速を決めているのは迎え角なので、
   そちらを直接見るのが正しかった

### 確認できたこと（各180秒の実測）

| | 弱 | 普通 | 強 |
|---|---|---|---|
| 何もしない相手への得点 | 46 | 85 | 95 |
| CPU 同士の決着数 | 3試合 | 3試合 | 7試合 |
| CPU 同士の得点 | 30対16 | 37対32 | 66対69 |
| 地面への自滅 | 0回 | 0回 | 0回 |
| 失速していた割合 | 8〜12% | 7〜8% | 9% |

直す前は地面への自滅が 180秒あたり 28〜40回、失速が 11〜33% だった。
同じ腕前どうしなら互角に、腕前が上がるほど強く速くなっている。

### 次にやること

- 実際に触って、特に「弱」が初見で勝てる強さかを見てもらう
- CPU 同士だと「強」は 26秒で1試合が終わる。人が相手ならもっとかかるはずだが、
  速すぎるようなら再出撃の仕組み（位置をばらす・短い無敵時間）を検討する

## 2026-08-12: 起動直後の甲高い音を修正

### やったこと

「スタート時に変な高い音が鳴り、エンジンを吹かすと通常のエンジン音になる」という報告。
原因は2つ重なっていた。

1. **発振器の初期値が 440Hz**。Web Audio の発振器は何も指定しないと 440Hz（ラの音）で鳴る。
   エンジン音は爆発の刻みを作る発振器で音量を揺らしているが、その刻みまで 440Hz で
   回っていたため、機関の音ではなく甲高い音になっていた
2. **段階の設定が空振りしていた**。ブラウザは操作があるまで音を鳴らせないので、
   エンジン音の実体ができるのはゲームが動きはじめたあと。ところがゲーム側は
   「段階が変わったときだけ設定する」作りだったため、実体ができる前の1回で
   「設定済み」と記録してしまい、実体には一度も届かなかった。
   スロットルを踏んで段階が変わって初めて設定が届く ―― これが「吹かすと直る」の正体

直し方は、発振器を作った時点で目的の段階に合わせることと、
音を鳴らせるようになる前に要求された段階を覚えておいて鳴らしはじめに適用すること。

### 確認できたこと

実際のゲーム画面で発振器の周波数を読んで確認した。

- 修正前: 音を起こした直後の基音 **440Hz**・刻み **440Hz** のまま。E を押すと 88Hz に変わる
  （報告どおりの症状を再現）
- 修正後: 音を起こした直後から基音 **64Hz**・刻み **24Hz**（巡航）。
  E を押すと 88Hz / 34Hz（全開）、離すと 64Hz / 24Hz に戻る

## 2026-08-12: 「コントロールが効かなくなる」不具合の修正

### 原因の切り分け

Tab キーによるフォーカス移動を疑ったが、実際にはキー入力は生きていた。原因は別の2つ。

1. **低速で立ち往生する** — 風見安定の効きを速度に比例させていたため、機首を上げ続けて
   速度をほぼ失うと、機首が上を向いたまま空中で止まり、舵も揚力もほとんど効かない状態になっていた
2. **天井が画面外にあった** — `ceilingY = -40` だったため、高く上がると機体が画面から消えていた

### 直したこと

- 風見安定の効きを速度の平方根にし、下限（0.3）を設けた。
  実測: 速度24・機首上向きの状態から、1秒ほどで機首が下を向いて落下に転じ、
  速度 90 → 223 → 389 と回復する（以前は上を向いたまま止まっていた）
- 天井を機体が見える位置（y=46）に移し、その手前（y=150）から下向きの力が強まるようにした。
  硬い壁で跳ね返すより自然で、機体を見失わない
- 撃墜されている 2.4 秒の間に「撃墜／再出撃まで N」を表示

### 飛行の数値への影響

巡航 288 / 全開 371、宙返り 210×297px・3.13秒は変わらず。
巡航のまま上昇を続けた場合の失速は 2.85秒→3.63秒とわずかに遅くなり、
