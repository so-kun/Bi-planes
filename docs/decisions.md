## 確定済み

### 2026-08-12: プロジェクトの基本方針（ユーザー要件）

- レトロゲーム Bi-Planes のブラウザ版リメイク。本家のシンプルな面白さは引き継ぎ、グラフィックとルールに手を加える
- 2人対戦。二機の飛行機を操縦し、相手を撃墜して得点を競う。規定点数に達したら勝ち
- リアルな操作性（急上昇での失速など）を実現する
- 操作: 上下 + 弾発射（本家準拠）に加え、スロットル操作と2種類の弾（7.7mm / 20mm）
- 耐久力制: 7.7mm は複数発、20mm は一撃で撃墜
- 被弾が増えるとエンジンパワーか旋回力が鈍る。被弾時は煙の演出
- グラフィックはカップヘッド風レトロカトゥーン
- 1画面固定、スクロールなし
- 気球がランダムで上昇し、撃ち落とすと得点
- 実装順: まず1Pのみ操縦できる状態 → プレイテスト → 納得したら残りを実装

### 2026-08-12: 技術スタック

- **Phaser 3 + TypeScript + 自作フライトモデル** を採用
- 理由: 描画・音・入力・シーン管理はエンジンに任せ、揚力・失速などの飛行力学だけ自作する。
  汎用物理エンジン（Matter.js 等）は揚力・失速を扱えず、挟むと操作感のチューニングが難しくなるため不採用

### 2026-08-12: 対戦形態

- **1台のキーボードでローカル2人対戦** を採用（P1: 左手側キー、P2: 矢印+右手側キー）
- オンラインは完成後の拡張候補とし、今回のスコープ外
- ゲームパッドと CPU 対戦も当初はスコープ外としていたが、**2026-08-12 に採用**した
  （末尾の「ゲームパッド対応」「コンピュータ操縦」を参照）

### 2026-08-12: サウンド方式

- **全て Web Audio で合成**（SFX はシンセ合成、BGM は1930年代スウィングジャズ風の自作シーケンス）
- 外部素材を使わず自己完結。ただしサンプルを聴いてユーザーが採用判断する（下記「検討中」参照）

### 2026-08-12: 効果音・BGM（採用）

### 2026-08-12: 実画面モック Rev.1 の判定（確定）

- **フィルム処理**: 既定は**「弱」と「標準」の中間**。**縦キズ（フィルムの傷）は不採用**
  ―― 作為的に見えるため。粒状感・ゴミ・露光ゆらぎ・ゲートウィーブ・ビネットは残す
- **ゲートウィーブ**: 現在の量（プリセット「弱」相当）で確定。
  フィルム強度を上げても揺れの量は増やさない（酔いへの配慮。設定でオフにもできる）
- **機体の表示サイズ**: 画面幅の **8%**。煙と発射炎の大きさは機体サイズに追従させる
  （機体だけ縮めると煙が相対的に大きくなり、承認時の見え方が崩れるため）
- **煙**:
  - 通常飛行中も**薄い白煙**を引き、飛行の軌跡が空に残ってしばらくして消える
  - 被弾時の煙は**黒く濃い**。白い軌跡と重なっても被弾が一目でわかる
- **HUD**: クリーム地＋黒枠の意匠を採用
- **武装の弾道**:
  - 7.7mm — 直線・高速（1500 px/秒）・画面全域に届く・連射（毎秒約11発）
  - 20mm — 低速（640 px/秒）・重力で落ちる山なり・射程約 700px・単発
  - どちらも**発射時に機首から炎（マズルフラッシュ）**が出る。20mm は大きく長い炎＋発射煙

### 2026-08-12: 弾道の射程と爆発（確定）

- **7.7mm の軌跡を細く**する（曳光の芯 1.8px・グロー 4.5px）。太いと画面が騒がしくなるため
- **射程を明示的に分ける**。7.7mm は画面幅の約 60%（765px）、20mm は約 37%（480px）。
  20mm は「懐に飛び込んで当てる」武器という位置づけを、数値で保証する
- **爆発は空中撃墜と地面への激突の2種類**を用意する:
  - 空中 — 閃光 → 全方位の火の玉 → 破片が放物線を描く → 黒煙が膨らんで数秒残る
  - 地面 — 火は上半分だけに立ち上がり、土煙が左右に広がる。衝撃波の輪は横長の楕円
- 火・燃え残り・土煙は、**提供イラストの煙の絵を色染めして作る**。別の絵を用意すると絵柄が浮くため。
  染めるとインクの輪郭線まで同じ色になるので、元絵を掛け合わせて線の濃さだけ戻している

### 2026-08-12: ロール操作と気球（追加）

- **ロール操作を追加**する。押すと機軸まわりに180度回り、正立と背面が入れ替わる（0.45秒）
- 見た目は提供いただいた**上面図・下面図を中間コマとして補間**する
  （0°側面 → 90°上面 → 180°側面の上下反転 → 270°下面）
- 操作キーは P1 = R、P2 = /
- **気球**は画面幅の 7.5%。下からランダムに上昇し、7.7mm でも 20mm でも割れる。
  当たり判定は球皮だけ（籠や索には当たらない）

### 2026-08-12: M1 実装時に確定したフライトモデルの数値

すべて `src/config.ts` に集約。プレイテストで触るのはこのファイルだけで済むようにしてある。

- **重力 320・揚力係数 0.015** — 宙返りの大きさが画面に対して見栄えするように決めた。
  実測で 268×272px を 3.1秒で一周する。これより揚力を強くすると、機体より小さい輪で回ってしまう
- **推力 [96, 150]** — 巡航 288、全開 371（のちに全開を 190 = 速度 421 に引き上げ。末尾参照）
- **操縦桿の効き 2.8 / 風見安定 4.0** — この比が、舵を引き切ったときの迎え角を決める。
  速いうちは失速せずに曲がれて、遅くなると失速する
- **舵の効きは速度の平方根で落とす** — 速度に比例させると揚力の項も同じだけ落ちてしまい、
  いくら遅くなっても迎え角が失速角に届かず、失速が起きなくなる
- 実測: アイドルで30度の上昇を続けると 1.4秒・速度145 で失速し、3.7秒で地面に落ちる

### 2026-08-12: 背面飛行の操作（確定）

- **機体基準**。背面では画面上の上下が入れ替わる
- 機体はピッチとロールしかできないため、右へ飛んでいた機が宙返りで左向きになると背面になる。
  正立に戻すにはロールが要る（実機と同じ）。ロール操作が飾りでなく必須の操作になる

### 2026-08-12: M1 プレイテスト第1回の判定

- **スロットルは巡航と全開の2段**にする。全開はボタンを押している間だけで、離すと巡航に戻る。
  3段階の切替式は、操作の手数の割に効果が読みにくかったため。押している間だけにすることで、
  「ここぞという場面で吹かす」という使い方が自然になる
- **エンジン音を小さく**する。鳴りっぱなしの音なので、単発の効果音と同じ音量だと耳につく。
  エンジン専用の音量（`AUDIO.engine`）を設けて 0.45 倍にした
- 飛行の挙動そのものは「全体的にいい感じ」との評価。変更なし

### 2026-08-12: ロールの操作キーを変更

- ロールは **左右キー** に割り当てる（P1 = A / D、P2 = ← / →）。R キーは廃止
- 左右で**回る向き**が変わる。左は下面図を、右は上面図を見せながら回る。
  どちらも 180度 回るので正立と背面の入れ替わりは同じで、見た目の回り方だけが変わる
- 上下（機首）と左右（ロール）が同じ手にまとまり、操作が直感的になる

### 2026-08-12: Git 運用の変更

- **区切りがついた時点で main にマージする**。PR を長く開いたままにせず、
  その都度 main に取り込むことで、main が常に「動く最新版」になっている状態を保つ
- main へ直接 push はしない。作業ブランチ → PR → マージ の流れは維持する
- マージ後は作業ブランチを main から切り直してから次の作業を始める

### 2026-08-12: 低速時の挙動と天井（不具合修正）

「途中でコントロールが効かなくなる」という報告への対処。原因は2つあった。

- **風見安定の効きを速度に比例させていた** ため、機首を上げ続けて速度をほぼ失うと、
  機首が上を向いたまま空中で立ち往生し、操縦不能になったように見えていた。
  効きを速度の平方根にし、下限（`minWeathervane` = 0.3）を設けた。
  落下しはじめれば必ず機首が下を向き、速度が戻って操縦を取り戻せる
- **天井が画面外（y = -40）にあった** ため、高く上がると機体が画面から消えていた。
  機体が見える位置（y = 46）で止め、その手前（y = 150）から下向きの力が強まるようにした。
  硬い壁で跳ね返すより自然で、機体を見失わない
- あわせて、撃墜されている 2.4 秒の間に「撃墜／再出撃まで N」を表示するようにした。
  何も出ないと、この間も操縦不能になったように見えるため

### 2026-08-12: 煙の出し分けとロールの速さ（プレイテスト第2回）

- **通常飛行の白い航跡は廃止**。常時出ていると画面が煩わしいため
- **損傷したときだけ煙を出し、色で当たりどころを示す**:
  - エンジン損傷 → **黒煙**
  - 操作系（舵）損傷 → **白煙**
  - 傷が深いほど間隔が詰まる。両方やられていれば両方の色が出る
- **ロールは 0.45秒 → 0.85秒**。一瞬すぎて手応えがなかったため。
  ロール中は画面内に働く揚力が減るので、遅くしたぶん高度も落ちる（機動としての代償が増える）

### 2026-08-12: キーが押しっぱなしになる不具合

- キーを押したまま別のタブやウィンドウへ移ると、キーを離したイベントが届かず、
  戻ってきたときに押しっぱなしの状態が残っていた
- 離脱と復帰の両方で押下状態を消すようにした。ブラウザのイベント（blur / focus /
  visibilitychange）は環境によって飛んでこないことがあるため、
  Phaser 側の通知（BLUR / FOCUS / PAUSE / RESUME / HIDDEN / VISIBLE）も併せて拾う

### 2026-08-12: 押しっぱなしの自動解除（Safari 対策）

上の修正のあとも Safari だけで押しっぱなしが残るという報告があった。Chrome では起きない。
特定のブラウザだけを狙って直すのではなく、**どのブラウザでも自力で復帰する仕組み**にした。

- **キーリピートを生存確認に使う**（`src/input/StuckKeyGuard.ts`）。
  キーを押し続けている間、ブラウザは keydown を繰り返し送ってくる。
  「押されているはずなのに、しばらく keydown が来ていないキー」は、
  実際にはもう離されているとみなして解除する
- **見送り時間は 1.6 秒**。OS のキーリピートが始まるまでの待ちは最長でも 1 秒ほどなので、
  それを十分に超える値にしないと、本当に押し続けているキーを誤って解除してしまう
- **繰り返しの keydown を一度も観測していないうちは働かない**。
  リピートを送らない環境で誤作動させないための安全弁
- デバッグ表示（Tab）に、いま押されているキーと解除した回数を出すようにした。
  効いているかどうかをユーザーが自分で確認できる
- 注記: この環境に WebKit を入れられなかった（Playwright のダウンロードが失敗する）ため、
  **Safari 実機での確認はできていない**。keyup が失われる状況を人工的に作って、
  1.7 秒で解除されることと、押し続けている間は解除されないことは確認済み

### 2026-08-12: 長時間プレイでフィルムの質感が消える問題

「しばらく実行しているとフィルタが取れていく」という報告への対処。
この環境（ソフトウェア描画）では再現しなかったが、原因として考えられるものを両方塞いだ。

- **時間の精度落ち**。粒とゆらぎは時間を種にしているので、時間が増え続けると
  浮動小数の精度が足りなくなり、粒が動かなくなって「膜が剥がれた」ように見える。
  時間を 16 秒（= 1/24 秒 x 384 コマ）で折り返し、シェーダの精度も
  使える環境では高精度（highp）を指定するようにした
- **時間の送り元を自前に**。ゲーム側から毎フレーム送る形だと、
  何かの拍子にパイプラインが作り直されたときに時間が進まなくなる。
  パイプライン自身が描画のたびに時刻を読むようにした
- **見張りを置いた**。カメラからエフェクトが外れていたら付け直す。
  強制的に外して 1 秒以内に復帰し、強度も保たれることを確認済み

### 2026-08-12: ゲームパッド対応（採用）

当初は「完成後の拡張候補・今回のスコープ外」としていたが、操作を詰める過程で採用した。

- **標準配列（mapping === 'standard'）のパッド専用**。PlayStation / Switch Pro / Xbox など。
  標準でないパッドは並びが機種固有で、番号をそのまま読むと別のボタンが操作に化けるため、
  つながっていても使わない。対応機種を絞ることで、番号の推測や機種ごとの分岐が要らなくなる
- **ロールは L / R ボタン**（ボタン 4 / 5）。スティック左右に置く案もあったが、
  機首を引きながら旋回するとスティックが斜めになり、ロールが暴発するため肩ボタンにした
- **機首はアナログ**。スティックを倒した量がそのまま舵の効きになる。
  飛行モデルは元から連続値を受け取る作りなので、キーボードの3値（引く／中立／押す）より
  細かく操れる。十字キーは倒し切りとして扱う
- 全開 = R2 / ZR（アナログのトリガーなので、浅く握っただけで全開にならないようしきい値を設けた）、
  7.7mm = ×／B、20mm = ○／A
- キーボードと同時に使える。両方触っている場合は深く入れているほうを採る
- **毎フレーム状態を読みに行く方式**にした。ブラウザのイベントに頼らないので、
  キーボードで悩まされた「押しっぱなしが残る」問題が原理的に起きない。
  パッドを抜き挿ししても、ボタンの立ち上がりの記録が残って暴発することはない

### 2026-08-12: 起動直後に甲高い音が鳴る不具合

「スタートした時に変な高い音が鳴っていて、エンジンを吹かすと通常のエンジン音になる」
という報告への対処。原因は2つが重なっていた。

- **発振器の初期値が 440Hz（ラの音）だった**。Web Audio の発振器は何も指定しないと
  440Hz で鳴る。エンジン音は基音の発振器2つに加えて、爆発の刻みを作る発振器で
  音量を揺らしているが、その刻みまで 440Hz で回るため、機関の音ではなく甲高い音になっていた
- **段階を決める呼び出しが、音を鳴らせるようになる前に空振りしていた**。
  ブラウザは操作があるまで音を鳴らせないので、エンジン音の実体ができるのは
  ゲームが動きはじめたあと。ところがゲーム側は「段階が変わったときだけ設定する」
  作りだったため、実体ができる前の1回で「設定済み」と記録してしまい、
  実体には一度も届かなかった。スロットルを踏んで段階が変わって初めて設定が届く
  ―― これが「吹かすと通常の音になる」の正体
- 直し方: 発振器を作った時点で目的の段階に合わせる。あわせて、
  音を鳴らせるようになる前に要求された段階を覚えておき、鳴らしはじめるときに適用する

### 2026-08-12: M2 に入るにあたっての決定（採用）

「検討中」に残っていた項目のうち、M2 の実装に必要なものを確定した。

- **勝利条件は 10点先取**。撃墜3点・気球1点・相手の自滅1点（提案どおり）。
  撃墜3〜4回ぶんで、1試合5分程度になる
- **性能劣化は当たりどころで決まる**（ランダムから変更）。
  機首側に当たればエンジン、尾翼側に当たれば舵。狙って壊し分けられるようになり、
  相手の煙の色（黒＝エンジン／白＝舵）で結果が読める。
  判定は、被弾点を機軸に射影して前後どちらかを見るだけ
- **金色のボーナス気球を入れる。撃つと自機が直る**（得点も通常の気球と同じ1点）。
  HP と性能低下の両方が戻る。負けている側の逆転手段になり、
  試合終盤まで気球を撃つ動機が続く。出る割合は 22%（`BALLOON.goldChance`）
- 金色は**色を染めたうえで後光を添える**。染めるだけでは夕焼けの空に埋もれて
  普通の気球と見分けがつかなかったため。後光は煙の絵を黄色く染めたものを流用している
  （別の絵を用意すると絵柄が浮くため）
- **画面端のラップアラウンド**（本家準拠）は M1 で実装済みのまま確定とする

### 2026-08-12: M2 の実装内容

- **2機が同じ空を飛ぶ**。1P は左から右向き、2P は右から左向きに出撃する
- 操作は 1P = W/S・A/D・E・F・G、2P = ↑/↓・←/→・Shift・, ・. 。
  上下が機首、左右がロールで両者そろえてある
- **ゲームパッドは2台まで**。標準配列のパッドをつないだ順に 1P・2P へ割り当てる
- **エンジン音は機体ごとに鳴らす**。相手の被弾による息継ぎが自分の音に混ざると
  何が起きたか分からなくなるため。2つ重なるぶん、まとめて音量を絞っている
- **計器は左右対称**に置く。名札と得点を画面の端側に寄せ、視線が自陣側にまとまるようにした
- 勝敗が決まると操作を受け付けなくなり、その場で静止する。Enter でやり直し
- M1 のテスト用キー（Z/X/C の被弾・修理）は廃止。相手がいるので要らなくなった

### 2026-08-12: コンピュータ操縦（採用）

当初は「完成後の拡張候補・今回のスコープ外」としていたが、
1人でも動かして確かめたいという要望から採用した。

- **AI は人と同じものしか出さない** ―― 機首の引き具合・ロール・スロットル・引き金の5つ。
  機体の中身を直接いじらないので、人に出せない動きにはならないし、
  失速も墜落も人と同じように起きる。飛行モデルを迂回する近道は作らない
- **考え方は「機首をどこへ向けたいか」を1つの角度に決めるだけ**。優先順位は
  地面が近い → 失速している → 狙う相手（敵機か気球）の未来位置、の順。
  地面と失速は何を措いても最優先にしないと、AI は真っ先に墜ちる
- **ロールを実機と同じ理由で使う**。機首を回すのに「押す」より「引く」ほうが素直なので、
  押し続けることになる場面では背面に返して引きに変える。
  ただし地面や失速から逃げている最中は回っている余裕がないので我慢する
- **腕前は3段階（弱・普通・強）**。違うのは狙いの許容範囲・迷ってから動くまでの間・
  未来位置の読みの正確さ・狙いの揺らぎ・撃ちはじめる距離・20mm を使うか。
  「弱」は 20mm を使わず、狙いも大きく揺れる
- **切り替えはキー1つで巡回**（切 → 弱 → 普通 → 強 → 切）。1P = V、2P = C。
  2P を任せれば1人で遊べ、両方に任せればデモとして眺められる
- 撃つと決めてから実際に引くまでに間を置く。反射で撃たれると理不尽に感じるため

### 2026-08-12: コンピュータ操縦の詰め（実測して直した3点）

最初の実装では、CPU 同士が 15秒で 11対1 になり、地面にもよく墜ちていた。
実測して原因を1つずつ潰した。

- **引き起こしは「今の高さ」ではなく「1.1秒先の高さ」で判断する**。
  今の高さだけで見ると、突っ込んでいる最中は手遅れになる。
  宙返りの半径が 135px ほどあるうえ、迷ってから動くまでの間もあるため。
  これで地面への自滅が 180秒あたり 28〜40回 → 0回になった
- **狙う高さに底を設ける**（地面から 150px）。地面すれすれの相手を追って
  一緒に突っ込まないようにする。撃つのを諦める代わりに墜ちない
- **失速させないために迎え角そのものを見る**。舵を引くと迎え角が増えるので、
  失速角の 0.8 倍を超えたら緩める。逆向き（迎え角を減らす向き）の舵は妨げない。
  速度で加減する案も試したが効かなかった ―― 失速を決めているのは迎え角なので、
  そちらを直接見るほうが正しい。失速していた割合が 11〜33% → 1〜12% に下がった

**実測値（各180秒）**

| | 弱 | 普通 | 強 |
|---|---|---|---|
| 何もしない相手への得点 | 46 | 85 | 95 |
| CPU 同士の決着数 | 3試合 | 3試合 | 7試合 |
| CPU 同士の得点 | 30対16 | 37対32 | 66対69 |
| 地面への自滅 | 0回 | 0回 | 0回 |
| 失速していた割合 | 8〜12% | 7〜8% | 9% |

同じ腕前どうしなら互角に、腕前が上がるほど強く速くなる。
なお「何もしない相手」は動かないので実際の人より与しやすい。

### 2026-08-12: 再出撃時の無敵・被弾時の震え・BGM の自動再生（採用）

- **再出撃直後は 2秒の無敵**。出てきたところを撃たれて何もできないのを防ぐ。
  弾は当たらずすり抜ける。CPU 同士だと、この隙がないと一方的な展開になりやすかった
- 無敵中は**機体が点滅して透ける**（毎秒6往復、濃さ 0.75 ⇄ 0.28）。
  見ただけで「今は当たらない」と分かるようにするため
- **被弾して傷むと機体が震える**。傷が深いほど大きく震える（最大 3.4px）。
  縦と横で周期をずらしてあるので、円を描かずブルブルと細かく揺れる。
  揺らすのは**見た目だけで、当たり判定は動かさない** ―― 傷ついた側が
  当たりにくくなってしまっては本末転倒なので
- **BGM は最初から鳴らす**。ブラウザの決まりで音を出せるようになった時点
  （最初のキー入力かクリック）で始める。B キーで止められるのは今までどおり
- CPU は無敵中の相手を撃たない。当たらないので弾の無駄になるため。
  ただし狙いは付け続ける（無敵が切れた瞬間に射線へ乗っているように）

### 2026-08-12: 全開の推力を引き上げ（150 → 190）

「スロットルを押したときのパワーをもう少し、加速したときのスピードをもう少し欲しい」
という要望への対応。**全開だけ**を上げ、巡航は変えない。

- 巡航 288 のまま、**全開 371 → 421**（+13%）
- 巡航との差が **83 → 133** に広がった。吹かす価値が上がり、
  「ここぞという場面で吹かす」という設計が効くようになる
- 加速も速くなった。速度差の9割に届くまで **3.5秒 → 3.0秒**
- 宙返りは 210×297 → 206×321。速いぶん輪はやや縦に伸びるが、画面には収まる
- 急上昇からの立て直しはむしろ楽になった（最低速度 92 → 143）

`tools/flight-probe.mjs` に**加速の測定**を足した。最高速だけ上げても、
そこへ届くのに時間がかかると速くなった気がしないため、
「巡航から全開にして、速度差の半分／9割に届くまでの秒数」を出すようにした。
